# V6 · 玩家自己的推理工作台

## 设计问题与解决方向

前五轮已解决基本通关、跨刷新撤销重做、手机跳转、英文关键操作与 CI 发布安全。
但老玩家必须在脑中或纸上记录「哪个物件可能在某个格位」，游戏只提供最终排列，不支持逐步排除。
V6 直接升级核心推理循环，而不改变六案的内容与约束：

读证物 → 标记候选 / 排除 → 调整当前排列 → 自己核对证据 → 结案。

### 产品原则

- 玩家控制所有格子；不猜测、不自动推导、不显示正确答案。不把「?」当成系统认证的可能。
- 一个物件对多个位置都可以标「可能」，多个物件对同一位置也可以标「可能」。
  允许自相矛盾的主观笔记，因为游戏不会代替玩家做决定。
- 笔记使用已公开的格位和物件标签，不额外读取或暴露作者正确解。
- 笔记与实际排序是两个平行数据；撤销/重做只影响排序，不能悄悄修改推理笔记。
- 本地永久保留（直至该案重置/结案，或手动清空）；无服务端、账号、SDK 和外部图片依赖。

### 已实现功能

1. 六案动态矩阵，4×4、5×5 或 6×6。使用原生 HTML 表格、行列标题、键盘可激活按钮与准确 aria-label。
2. 三态循环：· 未标记 / ? 可能 / × 排除；有图形和文字标签，不依赖颜色表达信息。
3. 以 details/summary 折叠呈现，避免新玩家第一眼就遇到大型表格。
4. 移动端矩阵可横向滚动，不挤坏页面；屏幕阅读器可读物件、格位、当前主观状态。
5. 每案独立随 session 存档；刷新、离开、语言切换不丢。旧 V5 存档自动得到安全的空白笔记。
6. 损坏的笔记矩阵丢弃笔记本身，不污染正常的排序存档。数据严格限制为 n×n 的 0/1/2。
7. 清空笔记需确认，并且不会清除当前排列、提示和归档状态。重置本案、清空全部进度会清空笔记。
8. 英文版对应翻译。所有已存在的正式判题、证据直达、撤销重做继续按原模型执行。

### 测试与门禁

- tests/logic/deduction_notes.test.mjs：数据结构合法性、复制边界、旧存档兼容、主观状态循环。
- tests/browser/ux_v6.py：320/390/1280px 实机尺寸模拟；点击、刷新、提示、清理确认、
  重置、四物/六物矩阵、损坏存档、英文 aria 与不横溢、控制台无异常。
- GitHub CI 对 V6 新 Node 和 Playwright 测试强制执行，沿用原有六案的所有门禁。
- 只有 CI 全绿后启动 Pages；itch ZIP 独立构建和上传。

### 尚未宣称的内容

这个功能的出现不等于游戏已获得真人玩家认可。G5 依然没有盲测数据。
仍需真实新玩家观察是否更愿意使用笔记、3 分钟内是否知道该做什么，才决定是否默认展开或添加教学。
真实 iOS Safari 与辅助技术实机测试仍然待验证。
