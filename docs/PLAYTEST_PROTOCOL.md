## 1. 为什么这一步不能由 Agent 代做

Agent 之间互相夸奖不是市场调查。本项目的形式化校验、语义审稿、独立盲审能发现**逻辑与文本缺陷**，
但**无法证明**：

- 人类玩家觉得这个谜题好玩 / 难度合适；
- 手机上真的读得下去；
- 提示梯度在真实卡壳时是否有用；
- 玩家是否愿意玩第二案。

这些只能由真人给出。

## 3. 试玩协议（给代为执行的人）

### 3.1 招募

- 找 **3–5 名没见过本项目**的成年人。
- **必须事先告知并取得同意**：会记录「完成情况 / 是否用了提示 / 用时 / 主观一句话」，不记录任何个人身份信息。
- 不能找已经读过案件 JSON 或本仓库的人——那不算盲测。

### 3.2 操作

1. 只给链接，**不要口头解释规则**。
2. 不提示答案，不指出"你应该点这里"。
3. 观察并记录（不打断）：
   - 第一次成功提交前，是否理解了「先后 / 相邻 / 间距 / 夹在中间」的区别；
   - 卡住时**先看证据**还是**先点提示**；
   - 有没有把 `distance` 的"相差三格"理解成"中间隔三件"；
   - 手机上是否有需要缩放才能读的内容；
   - 完成第一案后，**是否主动点"继续下一案"**。
4. 结束后问三个问题即可，不要引导：
   - 哪里最让你困惑？
   - 有没有哪句话你觉得可以有两种读法？
   - 还想玩下一案吗？为什么？

## 4. 决策规则

试玩结束后按以下规则决定下一版，**不靠感觉**：

| 观察到的现象 | 处置 |
|---|---|
| ≥2 人把 `distance` 读成"中间隔 N 件" | 全案改写措辞，并在玩法说明加图示 |
| ≥2 人在第一案 3 分钟内放弃 | 重做第一案的开场，不是加更多案件 |
| 有人说"提示直接给了答案" | 重写第三档提示 |
| 完成第一案的人里 <50% 点下一案 | 检查第一案结尾的钩子与"继续下一案"按钮位置 |
| 手机上出现横向滚动或需缩放 | 阻塞发布，先修布局 |
| 有人指出某条证据有两种读法 | 进语义审稿队列，修复后重跑全部校验 |
